# 01 赛题拆解与验收清单

> 依据：`2026绘蓝杯游戏开发赛题(B组).pdf`，题目一「2D 塔防游戏」。
> 结论先说：**题目一的基础内容是硬性全做，而且每一条都能被评委当场点开检查。**
> 所以策略是——先把 9 条基础内容全部变成「点了就能看」的东西，再谈进阶。

## 0. 通用规则（和代码无关，但会直接挂掉你）

| 要求 | 说明 | 你要做的事 |
|---|---|---|
| 必须用 Unity | 换引擎直接不认 | 用 Unity 6 LTS 或 2022.3 LTS |
| 素材可用网上/自制 | 但要能说明来源 | 建 `Docs/素材来源.md`，记录每个音乐/图片的 URL 和许可证 |
| 允许 AI 辅助，但必须对自己的代码负责，**禁止照搬他人项目** | 这是红线 | 每个脚本你都要能讲清「为什么这么写」，见 `07_答辩与代码讲解卡.md` |
| 插件使用前先问科协 | 比如 DOTween、Cinemachine 之类 | 不确定就先别用，纯 C# + UGUI 足够做塔防 |
| **全程提交至 GitHub，提前把链接给科协** | 说明评委会看 commit 历史 | 每天至少 1 次 commit，不要最后一天一次性上传 |

> ⚠️ 最容易翻车的一条：最后一天把整个工程一次性 push 上去，commit 历史只有一条。
> 这和你「从零学 C#」的说法直接矛盾，非常容易被质疑。**从第一天就开始提交。**

## 1. 基础内容逐条对照

### ① 建造升级

| 赛题原文 | 实现方案 | 代码位置 | 验收动作 |
|---|---|---|---|
| 玩家可以在地图指定区域建造防御设施 | 地块预制体（`BuildTile` + `BoxCollider2D`）铺成建造区，只有地块上能建 | `Tower/BuildTile.cs`、`Tower/BuildManager.cs` | 点地图空地 → 没反应或提示；点高亮地块 → 建塔 |
| 选中设施时，应能看到造价 | 底部建造栏每个按钮显示价格；悬停地块显示范围圈 | `UI/BuildButton.cs`、`Tower/RangeIndicator.cs` | 点塔类型按钮，读得出三个价格 |
| 建造和升级消耗资源 | `GameManager.TrySpendGold` 统一扣钱 | `Core/GameManager.cs` | 建塔后金币减少，数字对得上 |
| 击败敌人可获得资源 | `Enemy.HandleDied` → `AddGold(reward)` | `Enemy/Enemy.cs` | 打死怪金币上涨，飘出奖励 |
| **资源不足或位置不可用时，应给出明确提示** | `ToastMessage.Show("金币不足…")`；非地块点击也提示 | `UI/ToastMessage.cs` | 把钱花光再点建造 → 屏幕出现红字提示 |
| 至少一种设施可以升级 | 三种塔都能升 3 级 | `Tower/Tower.cs` 的 `TryUpgrade` | 选中塔 → 面板出现「升级 60」 |
| 升级后应有可感知的变化 | 伤害/射程/攻速变强 **+ 模型放大 12% + 升级音效** | `Tower.ApplyVisual` | 升级前后打同一只怪，掉血速度肉眼可见变快 |

> 评委常问：「你怎么证明升级真的生效了？」→ 答：`Tower.Stats` 读的是 `TowerData.levels[Level-1]`，
> 升级只是 `Level++`，所有数值随之变化；面板上的伤害数字也会同步刷新。

### ② 防御设施

| 赛题原文 | 实现方案 | 验收动作 |
|---|---|---|
| 至少 3 种功能不同的设施 | 箭塔（单体物理）/ 炮塔（范围物理）/ 冰塔（魔法 + 减速） | 三个按钮、三种明显不同的效果 |
| 自动寻找攻击范围内目标 | `EnemyRegistry.FindBestTarget`，选「最靠近终点」的 | 敌人进射程，塔自动转头开火 |
| 命中/范围伤害/减速生效时有清晰反馈 | 命中粒子 + 开火音效；范围伤害爆炸粒子；**减速时敌人变蓝白** | 三种塔各打一次，肉眼能区分 |

三者的设计意图（答辩要能说出这句话）：
- 箭塔：便宜、单体、DPS 高 → 前期主力
- 炮塔：贵、范围、攻速慢 → 打密集小怪
- 冰塔：伤害低但**魔法伤害无视护甲** + 减速 → 克制重甲和冲刺怪

### ③ 敌人

| 赛题原文 | 实现方案 | 验收动作 |
|---|---|---|
| 至少 3 种敌人 | 4 种：普通 / 冲刺 / 重甲 / 治疗 | 4 个 `EnemyData` 资产 |
| 至少一种有特殊机制 | 冲刺：每 4 秒加速 70% 持续 0.6 秒；治疗：每 3 秒给半径 2.5 内的同伴回 7% 血 | 盯着冲刺怪看它突然窜一下；治疗怪旁边的小怪血条回涨 |
| 差异影响玩家的布防选择 | 重甲护甲 7，箭塔 14 伤害只打 7 → 必须上冰塔；治疗怪不集火杀不掉 → 需要爆发 | 只造箭塔打第三关会明显吃力 |
| 沿路线前进，到终点扣生命 | `Enemy.Move` 走 `WaypointPath`，到最后一个点 `ReachBase()` | 漏怪后生命值 -1 |
| 每关至少 5 波 | `LevelWaves` 资产里配 5 波 | HUD 显示 `波次 x/5` |
| 波次间留布防时间 | `Wave.prepTime`，HUD 显示倒计时 | 每波结束有 8~10 秒可以造塔 |
| 后续波次通过组合/顺序/路线变化增加难度 | 第 3 波起出现重甲，第 4 波起出治疗，数量递增 | 每波感觉不一样 |

### ④ UI

| 赛题原文 | 实现方案 | 验收动作 |
|---|---|---|
| 开始与结束的 UI | 主菜单场景 + `ResultPanel` 胜利/失败面板 | 通关和失败各看一次 |
| 敌人头顶血条 | `WorldHealthBar`，血少变黄变红 | 放大看血条跟着掉 |
| 显示当前资源和波次进度 | HUD 左上金币、右上生命、顶部波次 | 打的过程中数字一直在变 |
| 暂停菜单：暂停 / 回主菜单 / 设置 / 返回游戏 | `PauseMenu`，Esc 呼出 | 按 Esc 四个按钮都在，点了都对 |

> 注意赛题这四项是并列的四个按钮，别只做「继续」和「退出」。

### ⑤ 游戏场景

| 赛题原文 | 实现方案 | 验收动作 |
|---|---|---|
| 搭建完整的关卡地图 | 每关一张地图：地面 Sprite + 路径 + 建造区 | 三关长得不一样 |
| 流畅的场景切换 | `SceneFader` 异步加载 | 切换不卡顿、不闪白 |
| 切换时使用淡入淡出 | 黑幕 Canvas，0.3s 淡出 0.4s 淡入 | 肉眼能看到黑一下再出来 |
| 至少 3 个可玩场景（教程小场景不算） | `Level_01/02/03` | Build Settings 里三个都在 |

### ⑥ 音效

| 赛题原文 | 实现方案 |
|---|---|
| 建造音效 | `Sfx.Build`，建塔时播 |
| 攻击音效 | `Sfx.TowerShoot`，每次开火播（音量调小，否则很吵） |
| 怪物死亡音效 | `Sfx.EnemyDeath`，可被 `EnemyData.deathSfx` 覆盖 |
| 背景音乐 | `AudioManager` 循环播放，主菜单/战斗两套 |

> 免费素材：freesound.org（音效）、incompetech / pixabay（音乐）。**每首都要记录来源和许可证。**

### ⑦ 灯光

| 赛题原文 | 实现方案 |
|---|---|
| 使用 URP 构建自己的项目 | 建工程时选 **Universal 2D** 模板（详见 03 文档） |
| 在场景中加入光源，美化地图 | 加 `Global Light 2D` 保证能看见；加 `Point Light 2D` 放在塔/熔岩/灯笼上做氛围 |

> 坑：URP 2D 下 Sprite 必须用 `Sprite-Lit-Default` 材质才会吃光，否则加多少灯都是全黑或全亮。

### ⑧ 新手引导

| 赛题原文 | 实现方案 |
|---|---|
| 可以是小界面引导、UI 帮助组件，方式不限 | `TutorialGuide`：第一关进场景时暂停，弹 4 页文字，点「下一步」翻页，只显示一次 |

想更稳一点：再在 HUD 上常驻一个「?」按钮，随时打开帮助面板。**两个都做，成本很低。**

### ⑨ 对象池

| 赛题原文 | 实现方案 |
|---|---|
| 对高频生成和回收的对象使用对象池 | `PoolManager`：敌人、三种子弹都走池；开波前 `Prewarm` 预热 24 个 |

答辩时要能说出「为什么要对象池」：
> 一波 20 只怪 + 每秒十几发子弹，如果每发都 `Instantiate/Destroy`，会产生大量 GC 垃圾，
> 触发 GC 时整帧卡顿（手机尤其明显）。对象池把「销毁」换成「SetActive(false) 放回队列」，
> 运行时几乎不产生新内存。

## 2. 进阶内容：挑 3 个做，别贪多

赛题「进阶内容」是加分项，**但基础项没做完时做进阶 = 扣分**。推荐按性价比排序：

| 进阶项 | 工作量 | 建议 | 备注 |
|---|---|---|---|
| 数据与逻辑分离（ScriptableObject） | 已完成 | ✅ 白送的分 | 本套代码天然就是这样 |
| 对象池 | 已完成 | ✅ 白送的分 | 同上 |
| 存档（PlayerPrefs / JsonUtility） | 已完成 | ✅ 白送的分 | 关卡解锁 + 音量 |
| 事件驱动 / 观察者模式 | 已完成 | ✅ 白送的分 | `GameManager.GoldChanged` 等 |
| 代码职责划分 | 已完成 | ✅ 白送的分 | 移动/血量/建造/UI 各自独立 |
| 编辑器扩展（关卡辅助工具） | 1 天 | 推荐 | 一键生成建造区格子，能讲出「提高迭代效率」 |
| Shader / Shader Graph | 2~3 天 | 有余力再做 | 例如塔受击闪白、地图发光边 |
| 技能树 / 背包 / 对话 | 3 天+ | ❌ 不建议 | 和塔防核心玩法关系弱，容易做成半成品 |

> 一句话判断标准：**能在 30 秒内演示给评委看的效果，优先做。**

## 3. 提交前必须自查的 6 件事

- [ ] 三个关卡都能**完整通关**（不是只做到第 2 波）
- [ ] 失败也能正常触发结算面板，并且能「重新挑战」
- [ ] 从主菜单 → 第一关 → 通关 → 第二关 全程无报错（Console 清空）
- [ ] 打包出一个 Windows exe，在**没有 Unity 的电脑**上双击能跑
- [ ] GitHub 仓库公开（或给科协加了权限），commit 历史覆盖整个开发周期
- [ ] `Docs/素材来源.md` 里每份外部素材都有出处

## 4. 「基础内容」实现顺序（别按 1~9 顺序做）

按依赖关系做，每天都能看到东西动起来：

```
敌人沿路径走  →  塔索敌开火  →  建造地块  →  金币经济  →  波次调度
      ↓                                                    ↓
   血条/死亡                                       胜负判定 + UI
      ↓                                                    ↓
   音效/粒子  ←────────  暂停 / 设置 / 引导  ←────  三关内容 + 淡入淡出
```

先让「一只怪能被一座塔打死」跑通，剩下都是在这个循环上加东西。
