# 04 预制体与场景装配手册

> 这是整套东西里**最需要照着做**的一份。脚本我已经写好，但 Unity 里「谁挂在哪里、字段拖什么」必须你亲手连一遍。
> 建议顺序：**A 数据资产 → B 预制体 → C 关卡场景 → D UI → E 检查清单**。
> 每完成一节就 Play 一次，别一口气搭完再跑——一次跑不通就不知道是哪步错了。

---

## 全局约定（先定好，省得后面乱）

| 约定 | 值 |
|---|---|
| 1 世界单位 | 1 个格子（Sprite 的 Pixels Per Unit 保持 100，一个 100×100 的格子图正好 1×1） |
| 相机 | Orthographic，Size = 6 |
| 渲染层级（Sorting Order） | 地面 0 / 路 -1 / 地块 1 / 高亮 2 / 塔 5 / 敌人 10 / 子弹 12 / 粒子 15 / 世界血条 20 |
| UI | Screen Space - Overlay，Canvas Scaler = Scale With Screen Size 1920×1080，Match 0.5 |
| 图层（Layer） | 新建一个 `BuildTile`（User Layer 8），只给地块用 |

# A. 数据资产

全部在 `Assets/_Project/Data/` 下：Project 窗口右键 → `Create > TD > ...`。

## A1. 敌人数据 ×4

| 资产名 | displayName | 颜色 | HP | 速度 | 护甲 | 奖励 | 扣血 | 特殊 |
|---|---|---|---|---|---|---|---|---|
| `Enemy_Grunt` | 步兵 | `#8FA3C8` | 55 | 1.5 | 0 | 9 | 1 | None |
| `Enemy_Runner` | 疾行者 | `#F2A25C` | 40 | 2.9 | 0 | 11 | 1 | **Dash**，interval 4，value 1.7 |
| `Enemy_Armored` | 重甲兵 | `#6E6E78` | 130 | 1.1 | 7 | 15 | 2 | None（护甲就是它的机制） |
| `Enemy_Healer` | 治疗者 | `#7ED08A` | 100 | 1.2 | 2 | 14 | 1 | **Heal**，interval 3，value 0.07，radius 2.5 |

- `sprite` 先留空或者用同一个白色方块，等美术资源到位再换。
- `scale`：步兵 1、疾行者 0.9、重甲兵 1.25、治疗者 1。
- 治疗者的 `specialValue = 0.07` 表示每次回复「最大生命的 7%」。

> 为什么数值这样配：疾行者血少但快 → 漏怪，逼你造冰塔拖住它；
> 重甲兵护甲 7，箭塔 14 伤害只能打 7（减半），但冰塔是魔法伤害、无视护甲 → 逼你造冰塔；
> 治疗者不集火打不死 → 逼你把炮塔放在路口。**这样「3 种塔都要用」是设计出来的，不是碰巧。**

## A3. 波次数据 ×3

`Create > TD > Level Waves`，命名 `Waves_Level01/02/03`。
每个资产 `waves` 数组 **Size = 5**（赛题硬性要求 ≥5 波）。

### `Waves_Level01`（教学关，firstPrepTime = 20）

| 波 | prepTime | groups（敌人 / 数量 / interval / startDelay） |
|---|---|---|
| 1 | 10 | 步兵 8 / 1.0 / 0 |
| 2 | 10 | 步兵 6 / 1.0 / 0；疾行者 4 / 1.2 / 3 |
| 3 | 10 | 步兵 10 / 0.8 / 0；重甲兵 2 / 2.0 / 4 |
| 4 | 10 | 疾行者 8 / 0.8 / 0；重甲兵 2 / 3.0 / 2；治疗者 1 / 0 / 1 |
| 5 | 0 | 步兵 12 / 0.6 / 0；重甲兵 4 / 1.5 / 2；治疗者 2 / 4.0 / 6 |

> 第 5 波 `prepTime` 填 0 无所谓——它是最后一波，之后没有布防时间了。

### `Waves_Level02` / `Waves_Level03`

直接复制 `Waves_Level01` 改数值，思路：

- **Level 2**：整体数量 ×1.3，重甲兵从第 2 波就出现，疾行者更多（逼你上冰塔）
- **Level 3**：整体数量 ×1.6，治疗者从第 3 波起出现，最后一波「重甲 6 + 治疗 3 + 步兵 15」

调数值的标准：**你自己用「一套常规打法」打，刚好剩 2~4 点生命通关**，就是好难度。
太难就降数量，太简单就加数量——别改伤害，改数量更好控。

# B. 预制体

全部放 `Assets/_Project/Prefabs/`。做法：在 Hierarchy 里搭好 → 拖到 Project 窗口 → 删掉场景里的临时物体。

## B1. 敌人预制体 `Enemy`

```
Enemy                      ← Enemy 脚本 + EnemyHealth 脚本
├─ Body                    ← SpriteRenderer（sorting 10）
├─ HealthBar               ← WorldHealthBar 脚本
│   ├─ Bg                  ← SpriteRenderer（sorting 20），深灰，scale (0.6, 0.09)
│   └─ Fill                ← SpriteRenderer（sorting 21），绿色，scale (0.58, 0.07)
└─ DeathVfx（可选）        ← ParticleSystem，Play On Awake 关掉
```

| 对象 | 组件与设置 |
|---|---|
| `Enemy` | `Enemy`：`body` ← Body，`deathVfx` ← DeathVfx；`EnemyHealth`：无字段 |
| `Body` | SpriteRenderer，`Sorting Order` 10；**不要**加碰撞体（索敌走 `EnemyRegistry`，不需要物理） |
| `HealthBar` | 位置 (0, 0.55, 0)，`WorldHealthBar`：`health` ← Enemy 上的 EnemyHealth，`fill` ← Fill，`fillRenderer` ← Fill 的 SpriteRenderer |
| `Bg` | `ui_health_bg`（见 08 文档），localScale (1, 1, 1) |
| `Fill` | `ui_health_fill`，localScale (0.95, 0.6, 1)，颜色在代码里按血量改 |

> 血条缩放的原理：`WorldHealthBar` 改的是 `Fill` 的 `localScale.x`，
> 并且同时修正 `localPosition.x`，所以无论 sprite 的 pivot 在哪，都是**从左边开始缩**。
> 这就是为什么 Bg/Fill 用同一个父物体居中摆放就行，不用手动改 pivot。

**必须验证**：把 Enemy 拖进场景，手动调 `EnemyHealth.Setup(data)` 不方便，
所以直接在 Play 里让 `WaveManager` 生成它（C 节搭完就能看到血条）。

## B2. 子弹预制体 ×3

三个长得不一样、脚本完全一样：

```
Projectile_Arrow           ← Projectile 脚本 + SpriteRenderer（sorting 12）
```

| 预制体 | Sprite | 备注 |
|---|---|---|
| `Projectile_Arrow` | 细长箭矢（朝上） | 尺寸小一点，0.15×0.35 |
| `Projectile_Cannon` | 圆球 | 大一点 0.35×0.35，可以加 Trail Renderer |
| `Projectile_Frost` | 冰晶/菱形（朝上） | 加浅蓝色调 |

- `Projectile` 的 `lifeTime` 默认 4 秒够用。
- `hitVfx` 可以先留空，D 节做完粒子再回来拖。
- **子弹的朝向代码里会自动算**，素材按「朝上」画就行（参考 `Projectile.AimTo`）。

## B3. 塔预制体 `Tower`

三种塔共用一个预制体，外观由 `TowerData.towerSprite` 决定：

```
Tower                      ← Tower 脚本（根物体）
├─ Body                    ← SpriteRenderer（sorting 5）
└─ Turret                  ← 空物体，位置 (0, 0.2)
    ├─ TurretSprite        ← SpriteRenderer（sorting 6），pivot 设在底部中心
    └─ FirePoint           ← 空物体，位置 (0, 0.45)
```

| 字段 | 拖什么 |
|---|---|
| Tower.`body` | Body |
| Tower.`turret` | Turret（会绕 Z 轴转向目标） |
| Tower.`firePoint` | FirePoint |
| Tower.`angleOffset` | **-90**（素材朝上时，角度计算要减 90°；素材朝右就填 0） |

> 为什么 `angleOffset = -90`：`Mathf.Atan2` 返回的角度是「相对 X 轴正方向（向右）」的，
> 而美术素材通常画成「朝上」。差 90°，所以减掉。

## B4. 地块预制体 `BuildTile`

```
BuildTile                  ← BuildTile 脚本 + BoxCollider2D
├─ Base                    ← SpriteRenderer（sorting 1），格子底图
└─ Highlight               ← SpriteRenderer（sorting 2），绿色半透明，默认关掉
```

| 设置 | 值 |
|---|---|
| Layer | `BuildTile`（新建的 User Layer 8） |
| BoxCollider2D | Size (1, 1)，Offset (0, 0)，**Is Trigger 随便**（只用点查询，不做物理） |
| BuildTile.`highlight` | Highlight |
| Highlight 的颜色 | `#66FF99`，Alpha 80 左右 |

> 地块必须是 1×1、位置对齐到整数格（0.5, 0.5, ...），否则塔会摆歪。
> 摆放技巧：先放一个，然后用 `Ctrl+D` 复制，按住 `Ctrl` 拖动会按 1 格吸附。

## B5. 命中/死亡粒子（可选，但强烈建议做）

`GameObject > Effects > Particle System`，命名 `Vfx_Hit` / `Vfx_Death`：

| 属性 | 建议值 |
|---|---|
| Duration | 0.3（命中）/ 0.6（死亡） |
| Looping | ❌ 关掉 |
| Start Lifetime | 0.15 ~ 0.3 |
| Start Speed | 2 ~ 4 |
| Start Size | 0.05 ~ 0.1 |
| Emission > Rate over Time | 0（用 `Bursts` 加一个 10~15 的爆发） |
| Color over Lifetime | 渐隐 |

做完拖给 `Projectile.hitVfx` / `Enemy.deathVfx`。

# C. 关卡场景（以 `Level_01` 为例）

## C1. 场景层级

```
Level_01 (Scene)
├─ Main Camera                  orthographic, size 6, z=-10
├─ Global Light 2D              intensity 1
├─ --- Systems ---
│   ├─ GameManager              空物体 + GameManager（startGold 160, startLives 10）
│   ├─ PoolManager              空物体 + PoolManager
│   ├─ WaveManager              空物体 + WaveManager
│   ├─ BuildManager             空物体 + BuildManager
│   ├─ Path                     WaypointPath（子物体 P0~P7 按路线摆）
│   ├─ TowerParent              空物体（塔的父级，保持场景整洁）
│   └─ RangeIndicator           RangeIndicator（子物体 Circle，圆 SpriteRenderer）
├─ --- Map ---
│   ├─ Ground                   SpriteRenderer，sorting -5，铺满整个视野
│   ├─ PathSprites              路径贴图，sorting -1（纯装饰）
│   └─ Tiles                    空物体
│       ├─ Tile_00 …           BuildTile 预制体实例，摆成建造区
├─ --- UI ---
│   └─ Canvas                   （见 D 节）
└─ EventSystem                  （建 Canvas 时自动生成，必须有）
```

## C2. 逐个字段怎么拖

### WaveManager

| 字段 | 拖什么 |
|---|---|
| `levelWaves` | `Waves_Level01` 资产 |
| `path` | 场景里的 `Path` |
| `enemyPrefab` | `Enemy` 预制体 |
| `enemyParent` | `--- Systems ---` 下新建空物体 `Enemies`（或不拖，敌人会挂在场景根） |

### BuildManager

| 字段 | 拖什么 |
|---|---|
| `towerPrefab` | `Tower` 预制体 |
| `towerParent` | `TowerParent` |
| `tileMask` | 选 `BuildTile` 一层（**只勾这一层**） |
| `rangeIndicator` | `RangeIndicator` |
| `infoPanel` | Canvas 下的 `TowerInfoPanel` |

### RangeIndicator

| 字段 | 拖什么 |
|---|---|
| `circleSprite` | 子物体 `Circle` 的 SpriteRenderer |

> `Circle` 用 Unity 内置的 `Knob` 或自己画一个圆环 PNG，**直径做成 1 个世界单位**
> （100×100 的图，PPU 100）。代码里 `scale = radius * 2` 就是按「直径 1」算的。
> 如果圆图大小不是 1，就先在 `Circle` 的 `localScale` 里手动校正，再让代码接管——会冲突，所以**图必须做成 1 单位**。

### Path（WaypointPath）

把 `P0 … P6` 空物体**按行进顺序**拖进 `points` 数组。
Scene 视图里会画出橙色折线，绿色球是起点、红色球是终点。

布局建议（相机 Size 6，视野约 21×12）：

```
(-9, 4) → (-6, 4) → (-6, -3) → (-1, -3) → (-1, 4) → (4, 4) → (4, -3) → (9, -3)
```

一条 8 个点的蛇形路，长度约 40 单位，敌人以 1.5 速度走完约 27 秒——足够塔打十几轮。

## C3. Build Settings

`File > Build Settings` → `Add Open Scenes`，**顺序无所谓**，但必须包含：

```
MainMenu
Level_01
Level_02
Level_03
```

漏了哪个，`SceneFader.LoadScene` 就会黑屏卡住（因为在 Build 里找不到场景）。

## D2. 层级树（照抄，命名一致方便对文档）

```
Canvas
├─ HUD                          ← HUD 脚本（常驻，不要关）
│   ├─ GoldText      (TMP)      左上，内容 "160"
│   ├─ LivesText     (TMP)      左上第二行，内容 "10"
│   ├─ WaveText      (TMP)      正上方居中，内容 "波次 1/5"
│   ├─ CountdownText (TMP)      正中偏上，内容 "下一波 10"
│   └─ PauseButton   (Button)   右上角，子物体 TMP 文字 "II"
├─ BuildBar                     底部居中，Horizontal Layout Group
│   ├─ Btn_Arrow                ← BuildButton 脚本
│   ├─ Btn_Cannon
│   └─ Btn_Frost
├─ TowerInfoPanel                ← 常驻空物体 + TowerInfoPanel 脚本
│   └─ Panel                     ← 默认隐藏（`panel` 字段拖这个）
│       ├─ TitleText     (TMP)
│       ├─ StatsText     (TMP)
│       ├─ UpgradeButton (Button) 子物体 TMP "升级 40"
│       └─ SellButton    (Button) 子物体 TMP "出售 +35"
├─ PauseMenu                     ← 常驻空物体 + PauseMenu 脚本
│   └─ Panel                     ← 默认隐藏
│       ├─ Title "已暂停"
│       ├─ Btn_Resume  "继续游戏"
│       ├─ Btn_Restart "重新开始"
│       ├─ Btn_Settings "设置"
│       └─ Btn_Menu    "返回主菜单"
├─ ResultPanel                   ← 常驻空物体 + ResultPanel 脚本
│   └─ Panel                     ← 默认隐藏
│       ├─ TitleText  (TMP)
│       ├─ BodyText   (TMP)
│       ├─ Btn_Next    "下一关"
│       ├─ Btn_Restart "重新挑战"
│       └─ Btn_Menu    "返回主菜单"
├─ TutorialGuide                 ← 常驻空物体 + TutorialGuide 脚本
│   └─ Panel                     ← 默认隐藏
│       ├─ TextLabel  (TMP)
│       ├─ StepLabel  (TMP) "1 / 4"
│       └─ NextButton (Button)
├─ SettingsPanel                 ← 常驻空物体 + SettingsPanel 脚本
│   └─ Panel                     ← 默认隐藏
│       ├─ MasterSlider + 数值 TMP
│       ├─ MusicSlider  + 数值 TMP
│       └─ CloseButton
└─ ToastMessage                  ← CanvasGroup + ToastMessage 脚本
    └─ Label (TMP)，默认 alpha 0
```

> ⚠️ **为什么是「常驻空物体 + 子 Panel」而不是把脚本直接挂在面板上？**
> 因为 Unity 不会对**未激活**的物体执行 `Awake` / `Start`。
> 如果脚本挂在默认隐藏的面板上，Awake 不跑 → 按钮监听没绑上 → 点「设置」毫无反应，
> 而且 Console 一条报错都没有。这是新手最容易被困住半天的问题。
> 所以：**脚本挂在常驻物体上，只把子 Panel 关掉**，所有脚本都按这个约定写好了。
> 如果你拖错成「panel = 自己」，脚本会在 Awake 里直接报错并禁用自己，不会静默失效。

四页引导文案（可直接抄）：

1. `敌人会沿橙色路径走向终点。每漏掉一只，你就会少一点生命。生命归零就失败了。`

3. `选中已建好的塔可以升级或出售。塔的等级越高，伤害和射程越强。`
4. `每种敌人都有弱点：橙色疾行者很快，灰色重甲兵只怕魔法伤害，绿色治疗者会给同伴回血。`
