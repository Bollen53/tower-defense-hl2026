# 16 双人协作规范

> Unity 项目和普通代码项目不一样：**场景（.unity）和预制体（.prefab）虽然是文本文件，但没法手工合并**。
> 两个人同时改同一个场景 = 后保存的把先保存的全部覆盖，而且没有提示。
>
> 所以协作的核心不是「怎么合并」，而是 **「怎么永远不需要合并」**。

---

## 一、第一原则：文件所有权

**每个文件只有一个主人。** 别人要改，先跟你说，由你改或者你同意后他改。

| 区域 | 主人 | 内容 |
|---|---|---|
| `Assets/Scenes/MainMenu.unity` | **队友** | 主菜单场景（他独占） |
| `Assets/Scenes/Level_01~03.unity` | **你** | 关卡场景（你独占） |
| `Assets/Scenes/round_1.unity` 等测试场景 | **你** | 临时测试，提交前可删 |
| `Assets/Scripts/UI/MainMenu.cs`、`LevelSelectPanel.cs`、`SettingsPanel.cs` | **队友** | 菜单相关脚本 |
| `Assets/Scripts/UI/HUD.cs`、`BuildButton.cs`、`TowerInfoPanel.cs`、`PauseMenu.cs`、`ResultPanel.cs`、`TutorialGuide.cs` | **你** | 关卡内 UI |
| `Assets/Scripts/Core/`、`Enemy/`、`Tower/`、`Wave/` | **你** | 游戏核心逻辑 |
| `Assets/Prefabs/` | 你（塔/敌人/子弹/地块）、队友（UI 预制体放 `Assets/UI/`） | 按目录分 |
| `ProjectSettings/EditorBuildSettings.asset`（Build Settings 场景列表） | **你** | 只由你添加场景 |
| `ProjectSettings/TagManager.asset`（图层、Tag） | **你** | 加图层前先在群里说一声 |
| `Docs/` | 谁写谁管 | 冲突了手动合并 |

> 如果队友也想加图层（比如 UI 层），让他把需求告诉你，**由你统一改 `TagManager`**——这个文件只有一个，两个人同时改必冲突。

## 二、Git 流程：一人一条分支

**不要两个人同时往 `main` 提交。**

```
main                  ← 只放能跑的版本
 ├─ feature/menu      ← 队友：主菜单
 └─ feature/level     ← 你：关卡
```

### 每天开始干活

```powershell
git checkout main
git pull                       # 先拿到对方最新的东西
git checkout -b feature/level  # 第一天建；之后直接 git checkout feature/level
git merge main                 # 把 main 的更新合进自己的分支（每天至少一次）
```

### 每天收工

```powershell
git add .
git commit -m "feat(level): 箭塔与建造流程打通"
git push -u origin feature/level
```

### 合并回 main（功能能跑通了才合）

```powershell
git checkout main
git pull
git merge feature/level
git push
```

> commit message 里的 `(level)` / `(menu)` 是**前缀约定**，一眼能看出这是谁改的、改的哪块。

## 三、四条硬规则

### ① 永远不同时打开同一个场景

Unity 没有文件锁。你改 `round_1`、他改 `MainMenu`，各存各的，互不影响。

**如果发现两人都在 `MainMenu` 场景里**，立刻约一个：「你在改还是我在改？」

### ② 场景里不要引用「别人场景里的东西」

主菜单要跳关卡，只能通过**场景名**：

```csharp
SceneFader.Instance.LoadScene(LevelConfig.SceneNames[0]);   // ✅ 只传名字
```

不能把关卡场景里的物体拖进主菜单的场景引用槽——**跨场景引用在打包后一定失效**。

### ③ 提交前必看 `git status`

```powershell
git status
```

**看到 `Library/`、`Temp/`、`*.csproj` 被打包进去，说明 `.gitignore` 出问题了**，停下来，不要 commit（几个 G 的垃圾进仓库就再也删不干净）。

### ④ `.meta` 文件必须一起提交

Unity 靠 `.meta` 记录每个资源的设置（PPU、pivot、脚本绑定）。

```powershell
git add .      # 这会同时收录 .cs 和 .cs.meta
```

**漏掉 `.meta` = 对方打开后所有引用全断**，画面全粉、脚本全丢失。

## 四、冻结的接口契约（你提供给队友的「插座」）

队友做菜单，需要调用你写的这些。**这些签名一旦定下，就不能随便改**——改了他那边立刻编译失败。

```csharp
// ① 关卡列表（场景名必须和 Build Settings 里一致）
LevelConfig.SceneNames        // string[]
LevelConfig.DisplayNames      // string[]
LevelConfig.Count             // int
LevelConfig.LoadLevel(index)  // 加载第 index 关（带淡入淡出）

// ② 场景切换（带黑幕）
SceneFader.Instance.LoadScene("MainMenu");

// ③ 存档
SaveSystem.IsLevelUnlocked(index)
SaveSystem.UnlockedLevel
SaveSystem.TutorialDone
SaveSystem.MasterVolume / MusicVolume
SaveSystem.Flush()

// ④ 音频
AudioManager.Instance.PlayMenuMusic();
AudioManager.PlaySfx(Sfx.Click);

// ⑤ 关卡内（他可能需要在菜单里重置）
GameManager.Instance.State      // Playing / Paused / Won / Lost
```

**约定**：队友只调这些，**不要改这些文件**。需要新功能（比如「关卡通关数统计」），找你加。

## 五、主菜单要做的三件事（给队友的清单）

| 功能 | 用哪个接口 |
|---|---|
| 点「开始游戏」→ 进第 1 关 | `LevelConfig.LoadLevel(0)` |
| 「关卡选择」→ 三个按钮，锁住的不能点 | `SaveSystem.IsLevelUnlocked(i)` |
| 「设置」→ 音量滑块 | `SaveSystem.MasterVolume/MusicVolume` + `AudioManager.Instance.ApplyVolume()` |
| 「退出」→ 退出游戏 | `Application.Quit()`（编辑器里要 `#if UNITY_EDITOR` 特判） |

**主菜单场景里必须有的物体**（否则他的 UI 点了没反应）：

```
MainMenu (Scene)
├─ Main Camera
├─ EventSystem          ← UI 点击必需
├─ Canvas
├─ AudioManager         ← BGM
└─ 各种面板
```

> ⚠️ `SceneFader` 不用他放——它是 `RuntimeInitializeOnLoadMethod` 自动创建的，任何场景都有。

## 六、集成检查清单（每周对一次）

- [ ] `git pull` 后能正常编译（Console 无红字）
- [ ] 主菜单 → 第一关 → 打完 → 回主菜单，全程无报错
- [ ] `git status` 里没有 `Library/`
- [ ] `File > Build Settings` 里场景顺序：`MainMenu` 在第一个（否则打包后启动就是关卡）
- [ ] 双方都在 `Assets/Scenes` 里只改自己的场景

## 七、真冲突了怎么办

| 冲突文件 | 处理 |
|---|---|
| `.cs` 脚本 | 可以手工合并（文本），看懂两边改了什么再合 |
| `.unity` 场景 | **不要手工合并**。选一边（通常是更新的那边），另一人的改动重做 |
| `.prefab` 预制体 | 同上，重做比合并快 |
| `ProjectSettings/*` | 通常选一边即可，注意别丢掉图层/Build Settings |

```powershell
git checkout --ours Assets/Scenes/MainMenu.unity      # 用我这边的
git checkout --theirs Assets/Scenes/MainMenu.unity    # 用他那边的
```

> 记住：**场景冲突的代价 = 重做一小时的点击**。所以规则 ①（不同时改同一个场景）比任何合并技巧都值钱。
