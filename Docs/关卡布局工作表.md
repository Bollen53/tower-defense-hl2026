# 关卡布局工作表（纸上设计 → 进 Unity 照抄）

> 用途：**在纸上（或 Excel）把三关设计完**，进 Unity 只做「照坐标摆」这种体力活。
> 好处：搭场景前就能发现「路径太短塔来不及打」「建造区离路太远够不着」——
> 这类错误在 Unity 里发现，意味着你要重摆 100 个格子。
>
> 填完这份表，后续可以让我写一个编辑器脚本**按坐标自动生成地块和路径点**，你连拖都不用拖。

---

## 一、坐标系约定

| 项目 | 约定 |
|---|---|
| 1 格 | 1 个世界单位（地块 Sprite 128px，PPU 128） |
| 格子中心坐标 | **整数**：(x, y)，x ∈ [-10, 10]，y ∈ [-5, 5] |
| 相机 | Orthographic，Size = 6 → 可见范围 x ∈ [-10.67, 10.67]，y ∈ [-6, 6] |
| 路径点 | 也放在整数坐标上，路径宽度 = 1 格 |
| 敌人起点 | `P0`，终点 | `Pn`（最后一个点 = 扣血点） |

> 为什么全用整数：摆地块时按住 `Ctrl` 拖动会吸附到 1 格，整数坐标能让「设计图」和「实际场景」完全一致，
> 不用事后微调。

## 二、先算清楚这三件事，再画地图

### 1. 路径够不够长

敌人在路径上走完的时间 = **路径总长 ÷ 速度**。这决定了他会被打几轮。

| 速度 | 走完 39 单位要多久 |
|---|---|
| 步兵 1.5 | 26.0 秒 |
| 疾行者 2.9 | 13.4 秒 |
| 重甲兵 1.1 | 35.5 秒 |

经验值：**第一关路径总长 ≥ 30，后面 ≥ 40**。太短的话敌人还没进射程就到了，塔再强也没用。

### 2. 塔能打多久（最容易被忽略）

敌人在一座塔的射程内停留的时间，取决于「路径离塔多远」：

`停留时间 = 2 × √(射程² − 垂直距离²) ÷ 速度`

以箭塔（射程 2.8，攻速 0.55s）打步兵（速度 1.5）为例：

| 塔离路径的距离 | 停留时间 | 能打几发 | 总伤害 |
|---|---|---|---|
| 0 格（贴着路） | 3.73s | 6.8 发 | ~95 |
| 1 格 | 3.49s | 6.3 发 | ~88 |
| 2 格 | 2.61s | 4.8 发 | ~67 |
| 2.5 格 | 1.68s | 3.1 发 | ~43 |
| ≥2.8 格 | 0 | 0 | **够不着** |

**结论：建造区必须有一边贴着路径 1~2 格以内。** 离 2.5 格以上，塔基本是摆设。
新手最常见的失败设计就是「建造区在空地中间，离路两格远」，打完发现一只怪都杀不掉。

### 3. 拐角是黄金点位

敌人在 90° 拐角处，会在同一座塔的射程内**走两段弦**，停留时间接近直线段的 2 倍。
所以**把建造区放在拐角**，比放在长直道旁边的效率高一倍——这是塔防地图设计的核心技巧。

同理：**蛇形路**（来回折）能让一座塔同时覆盖两条路径段，是「一张地图能打」的关键。

## 五、填完自查（5 分钟，能省你两小时）

- [ ] 每段路径的**两个端点都在整数坐标**上（否则敌人会斜着穿过格子）
- [ ] 相邻路径点的坐标**至少有一个分量相同**（只有横/竖段，没有斜线；斜线要额外算长度）
- [ ] 每段建造区**至少一边离路径 ≤2 格**
- [ ] 地图上**至少有一个拐角**被建造区覆盖（否则玩家会觉得「没地方放塔」）
- [ ] 起点 `P0` 在屏幕边缘（敌人从外面走进来才自然），终点 `Pn` 也在边缘或有个「基地」装饰
- [ ] 建造区**不要**覆盖整条路径（全都能建 = 无难度）
- [ ] 三关的路径**长度递增**（30 → 45 → 52），但可建造格**递减**（48 → 30 → 24）
